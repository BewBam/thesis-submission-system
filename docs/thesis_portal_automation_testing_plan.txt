AUTOMATION TESTING PLAN
THESIS SUBMISSION PORTAL
========================================

Phạm vi: năm chức năng chính
- Nộp bài
- File PDF
- Approve / Reject
- Nộp lại
- Push to DSpace

Thêm một lớp integration riêng: email workflow, chỉ local, không nằm trong 6 kịch bản Playwright.

Tài liệu này thay bản kế hoạch rộng trước đó. Không kiểm thử admin, filter, pagination, Google OAuth, hay component React riêng lẻ trong đồ án.


1. MỤC TIÊU

Tự động kiểm tra lifecycle luận văn trên portal đang chạy:

    Sinh viên nộp (kèm PDF)
        ->
    Phản biện approve hoặc reject
        ->
    (nếu reject) Sinh viên nộp lại
        ->
    Thư viện approve hoặc reject
        ->
    Giám đốc archive
        ->
    Thư viện / admin push item + PDF lên DSpace

Hai lớp test:

- API test (Jest + Supertest + PostgreSQL test): phần lớn case, gồm rule nghiệp vụ và PDF.
- E2E (Playwright): ít kịch bản, đi trên giao diện thật.

Không đặt mục tiêu 100% coverage. Không ghi số Passed/Failed vào luận văn trước khi chạy test thật.


2. HỆ THỐNG THẬT CẦN BÁM

Frontend: React + Ant Design, http://localhost:5173
Backend: NestJS, http://localhost:3000
Database: PostgreSQL thesis_portal
Đăng nhập test: username + password. System setting login_method phải là username.

Role dùng trong luồng này:

- student
- reviewer
- library_staff
- director

Admin không duyệt bài. Admin có quyền configure_system nên có thể gọi API push DSpace, nhưng luồng nghiệp vụ push thuộc thư viện.

Trạng thái submission:

- draft
- reviewing
- approved
- rejected
- archived

Không dùng các tên PENDING_REVIEWER, PENDING_LIBRARY, READY_TO_ARCHIVE.


3. LUỒNG NGHIỆP VỤ

3.1. Nộp bài

POST /submissions          multipart, nộp thẳng, status = reviewing
POST /submissions/drafts   lưu nháp, status = draft
POST /submissions/:id/submit   nộp từ draft, hoặc nộp lại

Điều kiện nộp:

- Đợt nộp đang open (khi nộp từ draft hoặc nộp mới).
- Sinh viên chỉ nộp với studentId của chính mình.
- Phải có ít nhất một reviewer.
- Phải có file PDF (file mới hoặc file đã lưu).
- Mỗi sinh viên chỉ một bài không phải draft tại một thời điểm.

3.2. PDF

Field upload: thesisFile
Chấp nhận: tên file kết thúc bằng .pdf, mime application/pdf hoặc application/x-pdf (mime rỗng vẫn được nếu đuôi .pdf).
Tối đa: 30 MB (THESIS_MAX_FILE_SIZE_MB).
File không phải PDF: HTTP 400, message "Thesis file must be a PDF".

3.3. Approve / Reject

Phản biện — POST /reviews/action
Body: { "submissionId", "action": "approve" | "reject", "comment" }

- Chỉ reviewer được gán, decision còn pending, submission đang reviewing.
- Reject bắt buộc comment.
- Một reviewer reject -> status = rejected.
- Một reviewer approve chưa đủ -> status vẫn reviewing, bài chưa vào hàng đợi thư viện.
- Tất cả reviewer approve, không ai reject -> status vẫn reviewing, nhưng đủ điều kiện library intake.

Thư viện — POST /reviews/library-action
Body: { "submissionId", "action": "approve" | "reject", "comment" }

- Chỉ library_staff.
- Bài phải đang reviewing, đã có review, không còn pending, không có decision reject.
- Approve -> status = approved.
- Reject bắt buộc comment -> status = rejected.
- action = archive -> 400 "Library staff cannot archive submissions".

Giám đốc — POST /reviews/director-action
Body: { "submissionId", "action": "archive" | "reject", "comment" }

- Chỉ director, bài phải đang approved.
- archive -> status = archived. Chưa gọi DSpace.
  Response: { "ok": true, "dspaceDeferred": true, "message": "Archived to period. Push to DSpace later from Archive configuration." }
- reject bắt buộc comment -> status = rejected.

3.4. Nộp lại

POST /submissions/:id/submit khi status là rejected hoặc approved.

- Status trở lại reviewing.
- Tạo lại vòng review (reviewer decision về pending).
- PDF cũ được giữ nếu không upload file mới.
- Bài archived không nộp lại được.
- Bài đang reviewing đã có reviewer quyết định thì không sửa / không nộp lại cho đến khi kết thúc vòng.

3.5. Push to DSpace

Archive và publish là hai bước.

Bước 1 — Director archive: chỉ đổi status portal thành archived.
Bước 2 — POST /archive-config/dspace/publish
Quyền: library_intake hoặc configure_system (thư viện hoặc admin).
Body:

    {
      "submissionIds": ["<uuid>"],
      "collectionId": "<dspace collection uuid>"
    }

Chỉ publish bài status approved hoặc archived. Status khác thì skip.
Kết quả từng bài nằm trong results[]: ok, dspaceItemId, bitstreamUploaded, message.

Cách đọc dspace_item_id:

- UUID không bắt đầu bằng dev-item- và dspace_publish_status = published: item thật, PDF lên bundle nếu bitstreamUploaded = true.
- Bắt đầu bằng dev-item- và mode = dev: DSpace chưa cấu hình, chỉ placeholder local. Status publish giữ pending.
- ok = false hoặc dspace_publish_status = failed: publish lỗi, bài portal vẫn archived, không mất dữ liệu.
- message "No DSpace collection selected": thiếu collectionId / collection của đợt.


4. CHIẾN LƯỢC

                /\
               /E2E\          6 kịch bản giao diện
              /------\
             /  API   \       toàn bộ rule của 5 chức năng
            /----------\

API test là trọng tâm vì rule nằm ở backend (quyền, trạng thái, PDF, DSpace).
E2E chỉ chứng minh người dùng đi được luồng trên Ant Design.

Không làm trong đồ án:

- Unit test phủ rộng service (service gọi SQL trực tiếp).
- Vitest / React Testing Library. UI không tách component LoginForm, SubmissionForm.
- Katalon Recorder làm bộ test chính.
- Google OAuth, quản trị user, filter, search, pagination.
- E2E trình duyệt cho email, và bật mail khi test URL deploy.
- Đưa DSpace production hoặc DSpace đầy đủ vào GitHub Actions.

6.6. Email (integration, chỉ local)

Không gửi SMTP ra ngoài. Mailpit nhận thư. Suite nộp bài / PDF / duyệt giữ email_enabled = false và không cần Mailpit.

Vì sao tách: system_settings.email_enabled được seed false và được ưu tiên hơn biến môi trường. Workflow gọi notifySafely: lỗi SMTP không làm fail nộp bài hay duyệt. Địa chỉ người nhận là username@hcmut.edu.vn.

Chỉ chạy khi không có API_URL. Remote không có hộp thư test.

Trước nhóm này, trên thesis_test:

    email_enabled = true
    smtp_host = 127.0.0.1
    smtp_port = 1025
    smtp_secure = false
    smtp_user và smtp_password để trống

Sau nhóm này, đặt lại email_enabled = false.

Mail gửi bất đồng bộ. Test poll GET http://127.0.0.1:8025/api/v1/messages theo tiêu đề bài cho đến khi có thư hoặc hết thời gian chờ.
